# Aigo for iPhone

Native SwiftUI client for the Aigo host daemon (protocol v1), v0.3.8. It pairs with
a PC, shows what every agent is doing, lets you answer approvals in a row,
chat with a session, drive its terminal, continue sessions, and start new work.
Priorities follow the host's `docs/NORTH_STAR.md`: the terminal must be
trustworthy first (SwiftTerm 1.20.0 since v0.3.6; socket reports, raw replays
and first-tap click since v0.3.7, for host v0.4.0+). Goal 2 since v0.3.8: search shows each
result's harness and where it runs, and **Continue** (`POST /continue`, `POST /continue/watch`) opens
the resumed session's terminal; shown only when host info `capabilities` has `sessions.continue`.

## Build

The Xcode project is generated with [XcodeGen](https://github.com/yonaskolb/XcodeGen):

```sh
cd ios
xcodegen generate            # writes Aigo.xcodeproj and Config/*.plist
xcodebuild -project Aigo.xcodeproj -scheme Aigo -configuration Release \
  -sdk iphoneos -destination 'generic/platform=iOS' \
  CODE_SIGNING_ALLOWED=NO build
```

- Spec: `ios/project.yml`; project `Aigo`; scheme `Aigo` (builds both targets).
- App target `Aigo` (bundle id `dev.aigo.app`, iOS 17, iPhone and iPad (`TARGETED_DEVICE_FAMILY` 1,2),
  version from `MARKETING_VERSION` in `project.yml`; CI sets the build number).
- Widget extension `AigoWidgets` (`dev.aigo.app.widgets`), embedded in the app:
  Live Activity on the Lock Screen and in the Dynamic Island.
- Swift 5 language mode, minimal concurrency checking. No signing settings,
  no entitlements. `Aigo/Assets.xcassets` holds the app icon (one 1024x1024
  universal PNG). The app target is compiled with `AIGO_APP` so shared code
  (the Live Activity intent) can call app-only code.
- Info.plists are generated by XcodeGen from the `info:` blocks in
  `project.yml` (they land in `Config/`, which is git-ignored).

## Layout

```
Shared/            compiled into both targets
  AigoActivityAttributes.swift   ActivityKit attributes + content state
  AigoIntents.swift              Approve / Deny LiveActivityIntent
  AigoPalette.swift              colors (graphite, lime, coral, ice)
  AigoFonts.swift                bundled fonts, text size, Font.aigo(...)
  AigoMark.swift                 icon mark + wordmark (also used by the widget)
  Fonts/                         Share Tech Mono (default), JetBrains Mono, Victor Mono,
                                 Geist Mono, Ubuntu Sans Mono, IBM Plex Mono (.ttf + licences),
                                 registered with UIAppFonts in both targets
Aigo/
  App/       AigoApp (entry), RootView (navigation), NotificationManager
  Model/     Codable mirrors of the host JSON, pairing link parsing, status wording, timeline events
  Net/       PinnedSessionDelegate (cert pin), APIClient (REST + error causes), LiveSocket (WS + reconnect)
  Store/     AppStore (state, events, digest, actions, address failover), TranscriptModel (chat WS),
             TerminalModel (attach WS: size/snapshot protocol), HostVault (Keychain),
             UpdateChecker (latest GitHub release, IPA link with Copy/Share),
             DesktopModel (remote desktop stream, input, monitors)
  Terminal/  TerminalSurface (SwiftTerm TerminalView kept at the PTY size; palette, fonts, gestures)
  Live/      LiveActivityController, IntentActions (app side of the island buttons)
  Views/     Home (the board: Needs you / Working / Review / Done tabs), AttentionCard + SessionCard,
             Session (Chat | Terminal | Changes), Search, NewWork, Pair, QR, Settings (Appearance)
AigoWidgets/       WidgetBundle + Live Activity / Dynamic Island UI
```

`AppStore` is the single `@MainActor` source of truth. It opens
`WS /api/v1/events`, replaces its state from each `snapshot` and applies
`session.updated/removed` and `inbox.updated/reset` events; `notify` events
become local notifications. Every change also refreshes the Live Activity.
It also keeps, in memory only, the last 100 timeline events for Home's
"Since you left" digest (status changes, finished turns with the agent's last
message, approvals answered; seeded from the snapshot's sessions, inbox and
recent notifications) and the arrival times of recent `session.updated`
events per session for the activity pulse on each row.

Home: status sentence → Needs you (a card stack: swipe right/left or tap
Approve/Deny; destructive commands always need a second "Yes, run it") →
Since you left → Everyone (swipe a row for Stop/Kill or Resume/Remove,
long-press for more). The header's host pill switches PCs and pairs another.

## Pairing and trust

1. On the PC: Aigo → Settings → Remote access → Pair a device. It shows a QR
   code / link `aigo://pair?h=<host:port>&a=<host:port,...>&fp=<sha256>&c=<code>&n=<name>`
   (`a=`: every address of the PC, best first: LAN, then Tailscale IP and MagicDNS name).
2. On the phone: scan the QR code, tap the link (the app registers the `aigo`
   URL scheme), paste it, or type address + 6-digit code + fingerprint.
3. The app tries the addresses in order (about 3 s each, the pinned
   fingerprint on every one), calls `POST /api/v1/pairing/complete {code, name, platform:"ios"}`
   through the first that answers and stores `{addr, addrs, fingerprint, token, hostId, hostName}` as one
   JSON blob in the Keychain (`kSecClassGenericPassword`, service
   `dev.aigo.app`). If the Keychain is unavailable (some sideloading setups),
   it falls back to a file-protected JSON file in Application Support.

The host uses a self-signed certificate, so the fingerprint is the trust
root: `PinnedSessionDelegate` hashes the leaf certificate DER with SHA-256 and
accepts the connection only when it equals the paired fingerprint. One
`URLSession` with that delegate serves both REST calls and WebSockets. Every
request carries `Authorization: Bearer <token>`; WebSockets also offer the
`aigo.v1` subprotocol.

The address list is refreshed from host info (`remote.endpoints` in the
`/events` snapshot). When the saved address stops answering (another
network), the app tries the others in order and switches to the first that
answers; Settings → Connection shows the address in use. Errors mention
Tailscale when the PC is not on the same network (see the host's
`docs/REMOTE.md`).

## Updates

The app checks `GET https://api.github.com/repos/YaselMS/aigo-ios/releases/latest`
at most every 6 hours (cached). When the tag is newer than the app's version,
Settings → About and a dismissible banner on Home show "Update available: vX".
It shows `https://github.com/YaselMS/aigo-ios/releases/download/<tag>/Aigo-unsigned.ipa` with Copy
and Share and opens nothing (#74): paste the link in Signulous → Upload IPA from URL.

## Known limits (v0.3.8)

- **Terminal** streams `WS /sessions/{id}/attach?history=3000` into SwiftTerm
  (`Terminal/TerminalSurface.swift`, 5,000-line scrollback) following the
  host's size/snapshot protocol (host `docs/API.md` §6): every `size` message
  resizes the terminal to the PTY's cols×rows first, then the snapshot frames
  up to `replayed` redraw it; no input is sent in between and nothing is
  replayed from a local cache (back from the background it sends `refresh`,
  or re-attaches if the socket died). Keys are encoded by SwiftTerm; the
  emulator's own query replies are dropped during a snapshot and otherwise
  sent as `{"type":"report"}` on the socket (hosts with `hello.terminal.report`,
  desktop v0.4.0+) or by REST (older hosts), so they never claim the PTY size.
  Snapshots are raw VT replays that reset the terminal themselves; the app
  writes them as they are. Touch: one finger scrolls,
  selects, or taps/drags as the mouse when the program enabled mouse
  reporting (the first tap both shows the keyboard and clicks); two fingers send the wheel (or arrows on the alternate screen).
  "PC size" sends `resize` with `mode:"view"` and scales the text to the PC's
  width; "Fit to phone" (also chosen by typing, unless PC size was picked)
  sends `mode:"interactive"`. Size reports are debounced (keyboard, rotation).
  The view keeps your scroll position unless you are at the bottom.
  `GET /screen` is still polled for the on-screen menu. Wide characters
  (CJK, emoji) can be misaligned in host snapshots (host limitation).
- **Background**: iOS suspends the socket shortly after the app leaves the
  foreground. The app reconnects and re-snapshots when it becomes active.
  There is no remote push; use the host's ntfy notifications for alerts while
  the app is closed.
- **Live Activity** is updated only while the app runs (no push token). It
  is marked stale after 30 minutes. Plain, non-destructive approvals get
  Approve / Deny buttons (a `LiveActivityIntent` that runs in the app); other
  requests open the app. Tapping it opens Home.
- **Questions** (Claude `AskUserQuestion`) are answered by picking the
  matching option in the session's on-screen menu (`POST /sessions/{id}/menu`).
  The host's approval endpoint only takes approve/deny for those. Questions
  from agents running outside Aigo must be answered in their own terminal.
- One active host at a time; switch with the host pill on Home or in Settings.
- iPad runs the same layout full screen (no iPad-specific layout). No file browser.
- Remote desktop (v0.3.3+): fitted JPEG stream from `WS /api/v1/desktop/stream`, view only until
  Take control; monitor list, control permission and cursor from host API §7d.
